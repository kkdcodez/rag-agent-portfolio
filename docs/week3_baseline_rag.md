# Week 3 — Baseline RAG

유방암 정보 검색 RAG의 가장 단순한 형태(Naive RAG)를 만들고 RAGAS로 측정한 기록. 이후 4~8주차의 모든 개선은 이 baseline과 비교한다.

## 1. 목표

화려한 성능이 목적이 아니라, **가장 기본적인 형태로 끝까지 한번 돌려 "기준점"을 만드는 것**이 목적이다. 이후 개선이 얼마나 효과 있는지 재려면 단순하고 명확한 출발선이 필요하기 때문이다.

## 2. 파이프라인

현재 구현된 RAG는 "문서를 미리 준비해두고 → 질문이 오면 관련 부분을 찾아 → 그것만 보고 답하는" 단순한 구조다. 각 단계에서 가장 기본적인 도구를 하나씩 골라 끼웠다.

| 단계 | 하는 일 | 사용 도구 |
|---|---|---|
| 1. 로드 | PDF에서 텍스트 추출 | PyMuPDFLoader |
| 2. 청킹 | 512자 단위로 분할(100자 겹침) | RecursiveCharacterTextSplitter (512/100) |
| 3. 임베딩 | 텍스트를 숫자 벡터로 변환 | intfloat/multilingual-e5-base (CPU) |
| 3. 저장 | 벡터 저장·검색 | Chroma |
| 4. 검색 | 질문과 비슷한 조각 top-5 회수 | (Chroma 유사도 검색) |
| 5. 생성 | 검색된 문서로 답변 작성 | OpenAI gpt-4o-mini |
| 6. 평가 | 답변 채점 | RAGAS 0.2 + Claude(채점) |

*- 생성과 채점을 다른 모델(gpt-4o-mini / Claude)로 나눈 이유: 같은 모델이 답하고 채점하면 자기편을 들어 점수가 부풀려지기 때문이다.*
*- 환경: Poetry(Python 3.11)로 라이브러리 버전을 고정해 재현성을 확보했다.*

## 3. 데이터

신뢰할 수 있는 공식 의료기관의 유방암 가이드라인 PDF **10종, 약 796페이지**를 사용했다. 국문·영문을 함께 넣어 한국어 질의와 영어 원문 근거를 모두 다룰 수 있게 했다.

| 구분 | 출처 | 문서 성격 |
|---|---|---|
| 국문 | 국립암센터 | 유방암 검진 권고안, 국민 암예방 수칙 |
| 국문 | 대한유방암학회 | 유방암 진료 권고안(임상 가이드라인) |
| 국문 | ESMO(국문 자료) | 환자용 유방암 안내 |
| 국문 | 기타 | 항호르몬제 안내 등 |
| 영문 | NCCN | 유방암 진료·검진 가이드라인 (침윤성, DCIS, 염증성, 전이성 등) |

- **내용 성격**: 검진 연령·주기, 위험 요인, 병기 분류, 아형(HER2 등), 치료(항호르몬제·수술·재건), 유전자 검사(BRCA), 전이성 관리, 식이 등 유방암 전반.
- **특징**: 임상 가이드라인이라 **표가 많고**(권고 등급표 등), 한국어 문서는 영어보다 페이지당 정보 밀도가 높다. 이 특징이 4주차 청킹 실험의 출발점이 된다.
- 각 조각에 **출처 메타데이터**(기관·문서명·페이지·언어)를 붙여, 답변에 출처를 명시할 수 있게 했다.

## 4. 평가 설정

- **Golden Set(평가용 질문) 10개**: 검진 연령, 위험 요인, HER2, 병기(1·2기), DCIS, 항호르몬제, 재건수술, BRCA, 전이성, 식이요법. 각 질문에 정답 기준(reference)을 작성.
- **세 지표** (RAG 흐름을 그대로 검사):

| 지표 | 무엇을 보나 |
|---|---|
| Context Precision | 검색이 관련 문서를 가져왔나 |
| Faithfulness | 답이 문서 내용에만 근거하나 (환각 여부) |
| Answer Relevancy | 답이 질문에 부합하나 |

## 5. 결과

| 지표 | 점수 | 분석 |
|---|---|---|
| Context Precision | **0.74** | 검색은 대체로 관련 문서를 잘 찾아왔으나, 병기 질문 등 일부에서 실패(0.00)가 발생 |
| Answer Relevancy | **0.87** | 답변이 질문 주제에 잘 부합하며, gpt-4o-mini 생성이 안정적임을 확인 |
| Faithfulness | **0.65** | 문서 근거가 절반 좀 넘는 수준. 출처·면책 보일러플레이트와 일부 환각이 점수를 낮춤 |

*(Faithfulness는 10문항 중 7문항 평균. 3문항은 RAGAS가 점수를 산출하지 못함(NaN).)*

## 6. 분석

1. **검색은 잘 된다** (Precision 0.74). 관련 페이지를 대체로 잘 찾아온다.
2. **답도 질문엔 잘 맞는다** (Relevancy 0.87). 동문서답하지 않는다.
3. **그런데 "문서에 있는 대로만" 답하는 건 부족하다** (Faithfulness 0.65). ← baseline의 약점.

**가장 중요한 발견 — "검색이 실패하면 모델이 지어낸다":**
"1기와 2기 차이" 질문은 검색이 실패(Precision 0.00)했는데, 모델은 "모르겠다"고 하지 않고 **자기 지식으로 병기 기준을 지어내 답했다**(환각). 의료 정보에서 이는 위험한 패턴이다. **이 한 사례가 baseline의 핵심 약점을 정확히 보여주며**, 검색이 부실할 때 다시 찾거나 답을 보류하는 로직이 필요해보이며, 이 부분은 추후에 Agentic RAG 실험할 때 수치적으로 증명하면서 설계해야겠다.

## 7. 한계 & 배운 점

- **점수와 실제 품질은 다를 수 있다**: 답변에 강제로 붙인 출처·면책 문구가 "검증 불가 문장"으로 잡혀 Faithfulness를 깎았고, 3문항은 아예 점수가 안 나왔다(NaN). 즉 **낮은 점수가 반드시 나쁜 답을 뜻하진 않는다** — 추후 평가 설계에서 보완할 지점.
- **검색이 약하면 환각이 따라온다**: 좋은 답의 전제는 좋은 검색이다. 추후에 검색을 개선해야겠다. 
- **환경을 고정해야 결과가 재현된다**: 라이브러리 버전이 섞이면 같은 코드도 결과가 달라진다. Poetry로 버전을 잠근 뒤에야 baseline이 안정적으로 나왔다.
- **로더를 바꾸면 인덱스도 다시 만들어야 한다**: 문서를 읽는 방식이 바뀌면 저장된 검색 데이터도 새로 만들어야, 노트북과 실제 검색 내용이 어긋나지 않는다.

## 8. 다음 단계 (Week 4)

Baseline에서 **검색이 실패하면 환각이 따라온다**는 것을 확인했다. 그렇다면 가장 먼저 개선해야 할 것은 검색의 재료인 **"문서를 어떻게 잘라 넣는가(청킹)"**다. 잘못 잘린 조각은 관련 정보를 흩뜨려 검색 정확도(Context Precision)를 떨어뜨리고, 이는 곧 환각으로 이어지기 때문이다. 그래서 Week 4는 다음을 진행한다.

- **데이터 진단**: 무작정 자르기 전에, 우리 문서가 실제로 어떤 성격인지(한·영 정보 밀도 차이, 표 편중, 반복되는 노이즈) 수치로 파악해야 근거 있는 청킹 전략을 세울 수 있다. 감이 아니라 데이터에 기반해 자르기 위함이다.
- **청킹 전략을 비교**: "몇 자로, 어떻게 잘라야 검색이 가장 정확한가"는 정답이 정해져 있지 않다. 여러 전략을 baseline과 같은 조건에서 돌려 Context Precision을 비교해야, 어떤 방식이 실제로 우리 데이터에 맞는지 증명할 수 있다.
- **PyMuPDFLoader vs pymupdf4llm 파싱 비교**: 표가 많은 임상 가이드라인 특성상, 표를 보존하는 파서(pymupdf4llm)가 더 나을 것이라는 가설이 있다. 그러나 "더 좋다"는 주장은 반드시 수치로 검증해야 한다. baseline(PyMuPDFLoader) 대비 실제로 검색·답변이 개선되는지 측정해, 도구 선택을 근거 위에 둔다.
