# Week 4 — 데이터 진단 (Data Diagnosis)

청킹 전략을 감이 아니라 **데이터 근거로** 세우기 위해, 문서를 자르기 전에 우리 데이터가 어떤 성격인지 먼저 진단한다.

## 1. 목적

"몇 자로, 어떻게 잘라야 하나"를 정하려면 먼저 데이터를 알아야 한다. 언어별 정보 밀도, 표 분포, 노이즈를 수치로 파악해 청킹 전략과 파서 선택의 근거를 만든다.

## 2. 진단 방법

PyMuPDF(fitz)로 PDF 10종을 읽어 페이지 단위로 분석했다. baseline 로더(PyMuPDFLoader)가 내부적으로 쓰는 것과 동일한 추출 방식이라, 진단과 실제 파이프라인의 기준이 일치한다.

- **토큰 수**: tiktoken으로 페이지당 토큰 측정
- **표·이미지**: 페이지 내 표/이미지 개수 카운트
- **노이즈**: 페이지 번호 패턴, 반복되는 짧은 줄(머리말/꼬리말) 감지

## 3. 진단 결과 — 언어별 요약

| | 한국어(ko) | 영어(en) |
|---|---|---|
| 문서 수 | 5 | 5 |
| 페이지 수 | 466 | 330 |
| 페이지당 평균 토큰 | 약 914 | 약 396 |
| 표 합계 | 171 | 17 |

## 4. 핵심 발견

**① 한국어가 영어보다 페이지당 정보가 2.3배 많다 (914 vs 396 토큰).**
토큰 분포에서 한국어는 750~2000에 넓게 퍼지고, 영어는 250~600에 몰려 있다. 같은 크기로 자르면 두 언어가 불균등하게 취급된다. 영어 한 페이지(~400토큰)는 거의 한 조각에 들어가지만, 한국어 한 페이지(~900토큰)는 여러 조각으로 쪼개진다.

**② 표는 한국어 가이드라인에 약 10배 집중돼 있다 (171 vs 17).**
특히 대한유방암학회(76개), 국립암센터 검진권고안(61개)에 몰려 있고, 영어 문서(NCCN)는 문서당 0~5개뿐이다. 표 보존 여부가 검색에 영향을 준다면, 그 효과는 주로 한국어 임상 가이드라인에서 나타날 것이다.

**③ 노이즈는 긴 한국어 문서에 집중돼 있다 — 단, 페이지번호 집계는 과다 계상됐다.**
page_number_hits가 국립암센터 검진권고안 827, 대한유방암학회 306으로 높게 나왔으나, 확인 결과 이는 **오탐이 섞인 값**이다. "숫자만 있는 줄"을 페이지 번호로 감지하는 규칙이 표 안 수치·참조 번호·연도(예: '2013'이 10회 감지)까지 잡았다. 실제 페이지 번호보다 부풀려진 값이므로 참고용으로만 본다.

## 5. 청킹 전략에 주는 근거

- **영어는 400 근처로 자른다**: 영어 페이지 평균이 388~437토큰이라, 조각 크기를 400 정도로 잡으면 한 조각이 한 페이지에 가깝게 대응해 맥락이 유지된다.
- **한국어는 512 정도로 자른다**: 한국어 페이지(~900토큰)를 적당한 크기로 분할한다. 조각을 크게(예: 900) 잡으면 한 조각에 여러 주제가 섞여 검색 정밀도가 떨어지므로 크게 두지 않는다.
- **노이즈 제거는 위치 기반으로 신중히**: 페이지번호 감지가 본문 숫자까지 잡으므로, "숫자만 있는 줄"을 전부 지우면 표·참조 데이터가 손실된다. 페이지 맨 위/맨 아래 줄에 한정해 제거해야 한다.
- **표 보존(pymupdf4llm) 비교의 검증 대상**: 표가 한국어 가이드라인에 집중돼 있으므로, "표를 보존하는 파서가 검색을 개선하는가"는 한국어 문서에서 검증하는 것이 타당하다.

## 6. 다음 단계 (week4_chunking_experiments.ipynb)

이 진단을 근거로 청킹 전략(언어별 크기 차등 + 위치 기반 노이즈 제거)을 설계하고, PyMuPDFLoader 대비 검색·답변이 실제로 개선되는지 실험으로 검증한다.
