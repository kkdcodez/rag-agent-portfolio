# Week 5 — Retrieval 고도화 (Retrieval Strategy)

4주차에서 확정한 청킹(G2, 클렌징 없음, PyMuPDFLoader)을 고정하고, **검색 단계만 격리해 개선**한다. 데이터 밑단 정리(전처리)부터 시작해 Hybrid → Rerank → Multi-Query를 하나씩 얹으며 각 기법의 기여도를 측정한다.

## 1. 목적

Dense(임베딩) 단독 검색의 약점을 보완해 "무엇을 찾는가"와 "찾은 것 중 무엇을 위에 놓는가"를 개선한다. 사전 로우레벨 검증에서 확인한 두 가지 문제가 출발점이다.

- **인덱스 노이즈**: 한글 문서 뒤쪽 참고문헌·색인이 chunk로 다수 인덱싱됨
- **임베딩 변별력**: e5-base는 무관 문장도 유사도 0.79로 높게 주고, HER2 양성/음성 같은 도메인 미세 구분을 하지 못함(0.937)

## 2. 실험 히스토리 개요

| 단계 | 실험 대상 | 결론 |
|---|---|---|
| 5-0 | 참고문헌·색인 제거 전처리 | **채택** — 인덱스 19% 감량, 부작용 없음 |
| 5-1 | BM25 / Dense / Hybrid(RRF) | **Hybrid 채택** — 고질 문항 해소 |
| 5-2 | Cross-Encoder Rerank | **채택** — Faithfulness 최고 |
| 5-3 | Multi-Query | **미채택** — 답변 생성 실패 사례 발생 |

**공통 조건**: 청킹 G2 고정 / 평가셋 golden_set_v1(한국어 20 + 영어 10) / 생성 gpt-4o-mini / 채점 gpt-4o-mini / 지표 해석은 Context Precision 중심 + 답변 텍스트 정성 검증 병행.

## 3. 5-0 — 참고문헌 노이즈 제거

**설계**: 헤딩 기준으로 문서 뒤쪽 참고문헌·색인을 제외. 자동 스캔은 후보 제시용이고 최종 컷 페이지는 경계 육안 확인 후 확정한다(4주차 클렌징이 검색 앵커를 지워 실패한 전철을 밟지 않기 위함).

**예외 처리**: kbcs 문서는 참고문헌이 문서 끝이 아니라 **챕터마다 산재**해 있어 "이 페이지부터 끝까지" 방식이 통하지 않았다. 페이지 단위 **인용-밀도 필터**(줄의 35% 이상이 인용 패턴이면 참고문헌 페이지로 간주)로 82개 페이지를 개별 제외했다. threshold를 0.5에서 0.35로 낮춘 이유는, 페이지마다 반복되는 챕터 탭·머리말이 인용 밀도를 희석시켜 실제 참고문헌 페이지가 0.46~0.49로 걸리지 않았기 때문이다.

**결과**

| 지표 | 원본(P0) | 제거(P1) | 델타 |
|---|---|---|---|
| chunk 수 | 2,773 | 2,240 | −533 (−19%) |
| faithfulness | 0.760 | 0.778 | +0.018 |
| answer_relevancy | 0.551 | 0.613 | +0.062 |
| context_precision | 0.899 | 0.901 | +0.002 |

**핵심 발견**: 인덱스의 19%를 제거했는데도 어떤 지표도 떨어지지 않았고, **문항 단위 CP 하락이 0개**였다. 참고문헌 chunk는 검색에 기여하지 않는 "죽은 살"이었다. 4주차 클렌징(머리말 제거 → 검색 악화)과 대비되는 결과로, 같은 "제거"라도 대상이 진짜 노이즈인지가 결과를 가른다.

**→ 채택**. 특히 BM25는 참고문헌의 저자명·저널명 키워드에 오염되기 쉬우므로, Hybrid 도입 전에 제거를 완료한 순서가 유효했다.

## 4. 5-1 — Hybrid Search (BM25 + Dense + RRF)

**설계**: BM25(sparse)와 Dense를 각각 상위 20개씩 검색해 RRF(k=60)로 융합. BM25는 한국어 형태소 분석(kiwipiepy, 내용어만 추출)을 적용했다. 결합 로직을 명시하기 위해 EnsembleRetriever 대신 RRF를 직접 구현했다.

**결과**

| retriever | Faithfulness | Answer Rel. | Context Precision | KO CP | EN CP |
|---|---|---|---|---|---|
| Dense | 0.749 | 0.612 | 0.907 | 0.960 | 0.801 |
| BM25 | 0.654 | 0.448 | 0.858 | 0.904 | 0.766 |
| **Hybrid** | **0.778** | 0.609 | **0.938** | **0.988** | **0.837** |

**핵심 발견**

- **단독 성능은 Dense 우세**(BM25는 6승 3패로 열세)이나, **융합하면 두 언어 모두 최고**가 된다. 두 검색기의 **실패 패턴이 서로 달라** RRF가 각자의 구멍을 메웠다.
  - 식이요법: BM25 0.00 → Hybrid 0.92 (Dense가 구제)
  - 1기·2기: Dense 0.45 → Hybrid 0.95 (BM25가 구제)
- **4주차부터 모든 청킹 전략에서 실패하던 "1기와 2기" 문항이 해소**됐다. Dense는 "남성 유방암 발생률" 같은 무관 chunk를 가져왔으나, BM25가 "1기", "2기"라는 정확한 표현으로 병기 관련 chunk를 잡았다. 청킹으로 풀지 못한 문제가 검색 방식으로 풀린 사례.
- **가설의 절반은 빗나갔다**: "고유명사(HER2, BRCA)는 BM25가 강할 것"으로 예상했으나, HER2 질문은 Dense가 이미 정확히 처리하고 있었다. BM25의 실제 기여는 고유명사보다 **짧고 정확한 표현 매칭**이었다.

**→ Hybrid 채택** (개선 5 / 악화 2 / 동일 23).

## 5. 5-2 — Cross-Encoder Re-ranking

**설계**: Hybrid로 top-20을 검색한 뒤 bge-reranker-v2-m3(다국어 Cross-Encoder)로 재정렬해 top-5를 선택.

**결과**

| retriever | Faithfulness | Answer Rel. | Context Precision |
|---|---|---|---|
| Hybrid | 0.778 | 0.609 | **0.938** |
| **Hybrid + Rerank** | **0.803** | 0.611 | 0.933 |

**핵심 발견**

- **CP는 사실상 변화 없고(−0.005), Faithfulness가 +0.025로 4구성 중 최고**가 됐다. Rerank는 "무엇을 찾는가"가 아니라 **"찾은 것 중 무엇을 위에 놓는가"**를 바꾸므로, 순서를 보지 않는 CP는 이 개선을 포착하지 못한다.
- 순위 변화 육안 확인 결과, HER2 질문에서 부작용 관련 chunk가 밀리고 표적치료 정의가, 병기 질문에서 TNM 병기 구분 chunk가 상위로 재배치됐다. 로우레벨에서 관찰한 e5의 약한 변별력이 실제로 보정되는 것을 확인.
- **지표가 정성 품질을 놓친 사례**: "검진은 몇 살부터?" 문항은 CP가 1.00→0.68로 하락했으나 **실제 답변은 Rerank 쪽이 더 정확**했다. Hybrid는 "40세 이상 2년마다"만 제시해 40세 미만에게는 권고가 없는 것처럼 읽히는 반면, Rerank는 30세 이상 매월 자가촉진 · 35~40세 임상 유방 진찰 · 40세 이상 유방촬영술 · 70세 이상 근거 불충분까지 **연령대별 권고 전체**를 담았다. 원인은 골든셋 ground_truth가 "40세 이상 유방촬영술" 중심으로 좁게 작성되어 더 완전한 답이 감점된 것 — **모델이 아닌 평가셋의 한계**다.

**→ 채택**. 근거는 CP가 아니라 Faithfulness와 정성적 답변 품질.

## 6. 5-3 — Multi-Query (미채택)

**설계**: 원 질문을 LLM으로 3개 표현으로 변형해 각각 Hybrid 검색 후 RRF 융합, 재정렬 기준은 원 질문. 가설은 "답이 여러 항목에 분산된 질문은 단일 질문으로 top-5에 다 담기 어려우므로, 변형하면 분산된 근거를 더 넓게 회수할 수 있다"였다.

**결과**

| retriever | Faithfulness | Answer Rel. | Context Precision |
|---|---|---|---|
| Hybrid + Rerank | **0.803** | 0.611 | 0.933 |
| Multi-Query | 0.775 | **0.626** | **0.946** |

**가설이 맞은 부분**

- **검진 연령**: CP 0.68→1.00, Faith 0.67→1.00. 변형 질문이 base에 없던 chunk(가족력 기반 조기검진)를 신규 회수.
- **위험 요인**: CP 0.80→0.95. Hybrid+Rerank는 가족력·유전적 소인 2개만 답하고 AR 0.00이었으나, Multi-Query는 방사선 노출·연령·비만·음주 등 8개 항목과 위험 배수까지 서술.

**가설이 빗나간 부분 — 미채택 근거**

- **식이요법(결정적)**: **CP 1.00으로 검색은 최고였으나 답변은 "제공된 문서에서 확인할 수 없습니다"**(Faith 0.00, AR 0.00). Hybrid+Rerank는 채소·과일 섭취, 짜지 않게, 탄 음식 회피, 식사일기, 고열량 식품 보관 등 4개 항목을 구체적으로 답변했다. **관련 chunk를 찾고도 답변 생성에 실패**한 사례로, CP가 "답변 생성 가능성"을 보장하지 않음을 보여준다.
- **생검 유형**: 4종(FNA·코어·진공보조·절제 생검)에서 3종으로 줄어 **절제 생검이 누락**됐다. 회수 폭을 넓혔는데 오히려 항목이 빠졌다.
- **언어 누출**: 영어 질문에 대해 변형 질문 3개가 모두 한국어로 생성됐다. 프롬프트에 언어 제약을 명시했으나 지켜지지 않아, 검색 대상 언어가 의도치 않게 바뀌었다.

**성능 저하 원인 추정**

1. 변형 과정에서 원 질문의 초점이 넓은 표현으로 퍼짐
2. RRF는 여러 결과에 공통 등장하는 chunk를 선호 — 한 chunk에만 있는 결정적 근거가 밀림
3. fetch 후보가 4배로 늘어 원 질문이 찾은 좋은 chunk가 희석됨
4. 다국어 corpus에서의 언어 누출
5. Hybrid의 BM25가 이미 표현 불일치 문제를 상당 부분 해결한 상태여서 추가 이득이 적음

**→ 미채택.** 정성 비교 4건에서 Hybrid+Rerank 2승 / Multi-Query 1승 / 1무. 다만 분산형 질문에서는 명확히 유효했으므로, 전면 적용이 아닌 **질문 유형별 선택적 적용**을 향후 과제로 남긴다.

## 7. Ablation 최종 비교

| 구성 | Faithfulness | Answer Rel. | Context Precision |
|---|---|---|---|
| Dense | 0.749 | 0.612 | 0.907 |
| BM25 | 0.654 | 0.448 | 0.858 |
| Hybrid | 0.778 | 0.609 | 0.938 |
| **Hybrid + Rerank (채택)** | **0.803** | 0.611 | 0.933 |
| Multi-Query | 0.775 | 0.626 | 0.946 |

**최종 구성**: 참고문헌 제거 인덱스 → Hybrid(BM25 + Dense, RRF k=60) top-20 → Cross-Encoder Rerank(bge-reranker-v2-m3) top-5

## 8. Error Case 분석

**① BI-RADS 유방 밀도 4단계 (영어, CP 0.00)**
- **검색된 chunk**: 모두 BI-RADS **판독 범주(0~6)** 관련 — "BI-RADS category 4", "PPV 6.5%" 등
- **가설**: 질문이 묻는 것은 **밀도 범주(A~D)**인데, 해당 내용이 인덱스에 없거나 표 형태로 존재해 chunk로 잡히지 않았다. Multi-Query로 질문을 4가지로 변형해도 top-5가 완전히 동일했다는 점이 이를 뒷받침한다.
- **다음 단계**: 재검색으로는 해결 불가능한 **데이터 커버리지 문제**. 6주차에서는 근거가 없을 때 억지로 답하지 않고 **거절(refusal)**하는 로직으로 다루는 것이 적절하다.

**② 식이요법 — CP 고득점 · 답변 실패 (한국어)**
- **검색된 chunk**: CP 1.00으로 관련 문서를 정확히 회수
- **가설**: 검색은 성공했으나 회수된 chunk 조합이 답변 생성에 적합하지 않아 모델이 "확인할 수 없다"고 응답했다. 검색 품질 지표(CP)와 답변 생성 가능성이 분리되는 사례.
- **다음 단계**: 6주차 grade 노드가 "이 chunk로 답변이 가능한가"까지 판단해야 함을 시사.

**③ 질문 유형별 최적 전략 상이**
- **관찰**: 분산형 질문(검진 연령, 위험 요인)은 Multi-Query가, 나열형 상세 질문(생검 유형, 식이요법)은 Hybrid+Rerank가 우세했다.
- **가설**: 단일 검색 전략을 모든 질문에 일괄 적용하는 것이 최적이 아니다.
- **다음 단계**: 6주차 Agentic RAG에서 "이 질문에 재검색·질문 변형이 필요한가"를 판단하는 노드로 대응.

## 9. 한계 및 메모

- **평가 지표의 한계 확인**: 이번 주차에 RAGAS 수치와 실제 답변 품질이 어긋나는 사례를 세 번 만났다. (1) 검진 연령 — CP 하락했으나 답변이 더 완전, (2) 1기·2기 — "문서에 없다"는 정직한 진술이 Faithfulness에서 감점, (3) 식이요법 — CP 1.00인데 답변 생성 실패. **자동 지표만으로 판정하면 잘못된 결론에 도달**하며, 답변 텍스트 정성 검증이 반드시 병행되어야 한다.
- **골든셋 ground_truth 보강 필요**: 검진 연령 문항의 정답이 좁게 작성되어 더 완전한 답변이 감점됐다. 지금 수정하면 기존 실험과의 비교가 깨지므로, 평가셋 확장 시점(7주차)에 반영한다.
- **채점 모델**: 4주차는 Claude, 5주차는 gpt-4o-mini로 judge가 다르다. 주차 간 절대 점수를 직접 비교하지 않고, 각 실험 내부의 상대 비교로만 해석했다.
- **Multi-Query 재실험 여지**: 언어 누출을 코드로 차단(변형 질문 언어 필터)하고 fetch_k를 조정하면 결과가 달라질 수 있다. 이번에는 미채택으로 정리하되 선택적 적용 방식으로 재검토할 수 있다.
