# 결정 로그 (Decision Log)

## Week 3
- PDF 로더 = PyMuPDFLoader (baseline) — 빠르고 안정적, pymupdf4llm는 미검증이라 4주차 실험으로 미룸
- 생성/채점 모델 분리 (생성 gpt-4o-mini / 채점 Claude) — self-preference 편향 회피
- 임베딩 = multilingual-e5-base (CPU) 
- 의존성 = Poetry — 버전 충돌로 재현성 깨져서 버전 고정

## Week 4
- 청킹 = 언어별 차등 크기 (한국어 540/80, 영어 620/90) — 한국어가 영어보다 2.3배 밀도 높아, 한국어는 잘게·영어는 크게 잘라야 두 언어 검색이 함께 최적
- 노이즈 제거(클렌징) 미적용 — 켰더니 검색·생성 다 하락. 반복 머리말이 노이즈가 아니라 문서 제목·섹션명 등 검색 앵커였음
- PDF 로더 = PyMuPDFLoader 유지 (pymupdf4llm 기각) — 표 markdown이 자연어 임베딩엔 노이즈이고 chunk를 파편화, 표 많은 한국어에서 가장 악화
- 평가셋 = 이중언어 golden_set (한국어 20 + 영어 10) — 영어 청킹 효과를 검증하려면 영어 질문 필요, NCCN 문서 근거로 출제

## Week 5
- 한글 문서 참고문헌·색인 제거 (인덱스 19% 감량) — 로우레벨 검증에서 발견한 노이즈. 제거 후 세 지표 개선·문항 단위 부작용 0. kbcs는 챕터별 산재라 인용-밀도 필터(0.35)로 페이지 단위 제거
- Retrieval = Hybrid(BM25+Dense, RRF k=60) 채택 — CP 0.907→0.938, 4주차 고질 문항(1기·2기) dense 0.45→0.95로 해소. BM25(kiwipiepy 형태소)와 Dense의 실패 패턴이 달라 융합이 서로의 구멍을 상쇄
- BM25 토큰화 = kiwipiepy 형태소(내용어만) — 공백 분리로는 한국어 조사·어미 때문에 매칭이 되지 않음
- Re-ranking = bge-reranker-v2-m3 (top-20 → top-5) 채택 — CP는 동급이나 Faithfulness +0.025. Rerank는 검색 대상이 아니라 순서를 바꾸므로 CP가 개선을 포착하지 못함
- Multi-Query 미채택 — 집계 CP는 소폭 높으나 식이요법 문항에서 답변 생성 실패(CP 1.00인데 무응답), 생검 유형 항목 누락, 영어 질문에 한국어 변형이 생성되는 언어 누출 확인. 분산형 질문에는 유효해 선택적 적용을 향후 과제로 남김
- 평가 방식 = 자동 지표 + 답변 텍스트 정성 검증 병행 — RAGAS 수치와 실제 품질이 어긋나는 사례를 3건 확인

## Week 6
- 평가셋 확장을 6주차 앞으로 이동 (30 → 42문항) — 기존 30문항에 거절 대상 질문이 없어 Agentic 분기를 평가할 수 없음. 7주차에 확장하면 baseline·Agentic을 각각 두 번 실행해야 함
- expected_behavior = answer / refuse / refer 3분류 — 근거가 없어 거절하는 경우와 근거는 있으나 개인 의료 판단이라 안내로 전환하는 경우는 실패 성격이 다름. 하나로 묶으면 근거가 있는데도 거절한 응답이 정답 처리됨
- grade 판단 = rerank score 단독 (LLM judge 미사용) — baseline 실패 원인이 LLM 판단 불안정성(qid 4가 프롬프트 수정만으로 답변→거절 반전). 라벨 검증에서 score가 세 구간(0.92~0.99 / 0.36~0.43 / 0.03~0.05)으로 분리됨을 확인. 구조와 LLM 판단을 동시에 바꾸면 개선 원인 특정 불가
- 임계값 = 0.5 통과 / 0.1 즉시 거절 — 0.5는 bge-reranker의 시그모이드 중립점, 0.1은 out_of_scope 관측값(0.03~0.05) 기준
- 재시도 소진 시 거절하지 않고 generate — 0.1~0.5 구간 문항 다수가 answer 대상이라 거절하면 오답. qid 4가 이 경로로 병기 분류 답변 생성 (baseline은 거절). 부작용으로 out_of_scope 2건이 generate 진입
- 재검색 결과가 나쁘면 이전 결과 유지 — 5-3 Multi-Query가 정상 검색을 악화시킨 사례의 재발 방지. qid 4에서 0.494 → 0.219 하락 시 실제 개입
- 거절 문구 = 언어별 고정 문구, LLM 호출 없음 — 응답 속도 유지, 영어 질문에 한국어 거절 문제 해결. 단 generate 경유 거절은 여전히 언어 제어 불가
- baseline 언어 버그만 수정하고 판단 실패는 유지 — 언어는 프롬프트 규칙 미준수(버그), 판단 실패는 6주차가 구조로 해결할 대상. 프롬프트로 덮으면 개선 대상이 소멸
- 구현 = src/rag/ 모듈 (노트북은 import만) — 8주차 재작성 회피. baseline과 Agentic이 같은 검색기·프롬프트를 강제 공유하게 되어 변수 격리가 코드 수준에서 보장됨
- RAGAS 측정을 7주차 4지표로 통합 — 동일 데이터 중복 실행과 judge 비용 2배 회피
- qid 37(score 0.917에서 거절)을 정상 동작으로 기록 — 문서에 타목시펜 부작용은 있으나 "0기 환자가 복용 중단 후 자궁 치료 우선" 개별 상황의 근거는 없음. 의료진 상담으로 넘긴 것이 안전한 처리
- 도메인 확장(부인암 문서, 위험도 자가진단)은 8주차 freeze 이후 — 문서 추가 시 인덱스가 바뀌어 3~7주차 수치 무효화
